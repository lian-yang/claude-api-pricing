Claude API effort parameter — what each level actually costs

The output_config.effort parameter is Anthropic's single-model cost dial: five levels that scale every output token — text, tool calls and thinking — without changing the rate card. Measured relative spend runs ~0.47× at low up to ~5.59× at max versus high, which turns a ~$4,035/month Opus 5.5 agent workload into anything from ~$2,445 to ~$17,805. Here are the levels, the defaults, the caching trap, and the math.

Effort is set via output_config.effort on Messages API requests or on a Managed Agent's model object, and works on all cloud platforms (Bedrock, Claude Platform on AWS, Google Cloud, Microsoft Foundry per their availability tables). ZDR- and HIPAA-eligible on /v1/messages with effort.

What effort actually bills

Effort changes how many output tokens a request consumes — not the price of any token. Anthropic is explicit that it applies to all tokens in the response: visible text, tool calls and their arguments, and thinking. Thinking tokens bill at output rates (on adaptive-thinking models like Opus 5.5 and Fable 5.2, that's the whole bill). So the cost dial is: effort × your model's $output rate. Input tokens don't move.

The fine print that changes bills

  • Defaults dropped on the new line. Opus 5.5 and Haiku 5.5 default to medium; every other effort-capable model defaults to high. An Opus 5.5 request with no effort set runs one level cheaper than the same request on Opus 5 — check you're not comparing bills across different implicit levels.
  • The caching trap. Changing top-level effort between requests invalidates prompt caching (it shapes the rendered prompt). Per-message effort changes — supported on Fable 5.2/5.1, Opus 5.5/5, Sonnet 5.5 and Haiku 5.5 — preserve the cache. In cached conversations, pick a level and hold it; on models without per-message support, varying per turn re-pays your input bill.
  • Model quirks return 400s. On Opus 5.5, thinking: {"type": "disabled"} errors at every effort level (adaptive thinking is always on). On Sonnet 5.5 and Haiku 5.5, disabled works at high and below but 400s at xhigh/max — use adaptive there. Sonnet 5.5's lowest thinking setting, between_tools, also 400s at xhigh/max and locks effort for the conversation.
  • max_tokens is a hard ceiling on thinking + reply. Effort barely changes reply length — prompt for length instead — but higher effort means more thinking, and thinking counts toward max_tokens even when its content isn't returned. Anthropic recommends large max_tokens (e.g. 128K on Sonnet 5.5, from 64K on Opus 5 at xhigh/max).
  • Tool calls scale too. Lower effort means fewer, terser tool calls; higher effort means more calls, preambles and summaries. Subagents at low are Anthropic's documented pattern for cost control.

Where to start, per model

Anthropic's own recommendations, condensed: Fable 5.2 — start at high, step to xhigh only for measured long-horizon gains, keep max for ceiling measurements. Opus 5.5 — it's already at medium; sweep before going higher. Sonnet 5.5 — high default on the API, medium for well-specified agentic work and latency-sensitive chat. Haiku 5.5 — start at medium, drop to low for chat and short tool tasks. Opus 4.7/4.8 — start at xhigh for coding and agentic work. The repeated official warning: effort levels are recalibrated per model, so re-run the sweep rather than carrying settings across upgrades.

Cost-efficiency verdict: the expensive end of the dial is rarely where you want to be. Anthropic's docs say max "runs slower and costs more than at xhigh, often for only a small gain"; Artificial Analysis' November 2026 testing reached the mirrored conclusion — stepping up one model tier beats maxing out effort at like-for-like quality. In bill terms: max on Opus 5.5 (~$17,805/month on our workload) buys less than Fable 5.2 or Opus-tier upgrades at high. Run the sweep on your own evals and buy the cheapest level that holds.

FAQ

What does the Claude API effort parameter do?

It controls how many tokens Claude spends on a response — visible text, tool calls and thinking all scale with it — letting one model trade thoroughness against token cost. Set output_config.effort on the request (or effort on a Managed Agent's model object). Anthropic describes it as a behavioral signal rather than a strict budget: at lower levels Claude still thinks on genuinely hard problems, just less.

What are the default effort levels per model?

high on most models; medium on Claude Opus 5.5 and Claude Haiku 5.5. Setting effort explicitly to the model's default produces exactly the same behavior as omitting it. Opus 5 and earlier default to high, so Opus 5.5's medium default is one level below its predecessor's implicit setting.

How much more does max effort cost than high?

Roughly 5.59× the output tokens versus high, per the effort cost table Claude Code ships (community-documented, November 2026): low ~0.47×, medium ~0.74×, high 1×, xhigh ~2.41×, max ~5.59×. On our standard Opus 5.5 agent workload that's ~$4,035/month at high, ~$8,265 at xhigh and ~$17,805 at max. These are measured approximations, not rate-card lines — effort isn't billed separately, it multiplies output volume.

Does changing effort break prompt caching?

Changing top-level effort between requests invalidates cached prefixes, because effort shapes the rendered prompt. Per-message effort changes on supported models (Fable 5.2/5.1, Opus 5.5/5, Sonnet 5.5, Haiku 5.5) preserve the cache. Hold effort constant across any conversation that relies on cache hits; vary it across workloads instead.

Is max effort worth it?

Usually not on price. Anthropic's docs: max "runs slower and costs more than at xhigh, often for only a small gain" — reserve it for measuring ceilings. Artificial Analysis' November 2026 testing found stepping up one model tier more cost-efficient than maxing effort. The documented workflow is an effort sweep on your own evals, buying the cheapest level that holds quality.
